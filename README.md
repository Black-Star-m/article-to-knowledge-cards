# make-knowledge-cards

把一篇文章变成 5~8 张知识卡：标题 + 核心知识 + 简明解释 + 例子或自测问题。

## 1. 解决什么问题

粘贴一篇文章让模型"总结成卡片"，常见结果有三种：把原文每句话抄成一张卡（其实是摘要换了个排版）、为了凑够张数把一个知识点拆成两三张、以及把模型自己记得的常识补进卡片里冒充原文内容。第三种最危险，因为卡片看起来比原文更"完整"，而读者无法分辨哪句是原文说的。

这个 skill 把输出约束成**只讲原文真正陈述的一个知识点**，并把"张数服从信息量"写进硬规则：原文只支持 3 张就出 3 张并说明，纯会务信息可以直接出 0 张。它不生成可执行代码、不做联网抓取，本质是一份写给 agent 的提取规则 + 卡片格式。

## 2. 主要功能

| 功能 | 实际规则（`skills/make-knowledge-cards/SKILL.md`） |
| --- | --- |
| 输入 | 消息里粘贴的正文；本地 `.md` / `.txt` 或其他纯文本文件路径 |
| 输出 | 5~8 张卡，每张含标题、`核心知识`、`解释`、`例子或自测`；卡片按原文提出知识点的顺序排列 |
| 重要性筛选 | 只保留"跳过它读者会说出结论但不理解为什么"的点；寒暄、宣传式复述、读者已有背景被丢弃 |
| 排除项 | 一次性活动的会务信息（日期、地点、截止、自带物品、报名方式的公告通知）、原文的结构描述、没给理由的观点 |
| 去重 | 同义反复与构成一个概念簇的相邻句子合并成一张卡；跨卡不复述同一事实，需要关联时写成 `与 Card 1 呼应` |
| 不编造 | 原文没有的数字、机制、人名、标准值一律不补（哪怕是常识）；原文含糊就保持含糊 |
| 保留限定语 | "某研究表明""我记不清了""约"这类标记进入卡片，并写明原文没解释什么；不把存疑说法改写成定论 |
| 不凑数 | 少于 5 张时只出实际张数，并追加一行按原文语言写明真实张数（如 `源文本信息量仅支持 3 张卡，未凑数。`）；只为凑满 5 张而存在的卡直接删掉 |
| 不擅自纠错 | 原文自相矛盾处按原样保留，把张力写进该卡的自测问题或结尾说明 |
| 语言 | 卡片正文跟随原文语言；字段标签固定为中英双语 |
| 存文件 | 仅当用户要求时写到 `knowledge-cards/<原文名>.md`，内容与对话输出一致 |
| 拒绝 | 网页/URL、PDF、图片、音视频、Anki 导出（`.apkg`）、图形界面；用用户提问的语言拒绝并请其改为纯文本 |

本仓库不含运行 skill 所需的脚本：`scripts/quick_validate.py` 只做结构校验，不参与卡片生成。

## 3. 安装

本仓库把 skill 放在 `skills/make-knowledge-cards/`，而 Qoder 从项目级 `.qoder/skills/` 或用户级 `~/.qoder/skills/` 加载，因此需要复制过去：

```bash
# 用户级（所有项目可用）
cp -r skills/make-knowledge-cards ~/.qoder/skills/

# 或项目级（当前项目可用）
mkdir -p .qoder/skills && cp -r skills/make-knowledge-cards .qoder/skills/
```

然后重启会话或执行 `/skills reload`，用 `/skills list` 确认 `make-knowledge-cards` 已加载。

## 4. 使用方法

```
/make-knowledge-cards 把这篇做成知识卡
<在这里粘贴文章正文>
```

给文件路径：

```
/make-knowledge-cards tests/sample-rice.md
```

要求落盘就加一句"存成文件"。信息量不足时不要要求"至少 5 张"——那会直接违反 skill 的不凑数规则。

### 给其他 agent 用

`skills/make-knowledge-cards/agents/openai.yaml` 是给非 Qoder agent 的加载清单：入口指回 `../SKILL.md`，声明只需 `read_file`，默认模型 `gpt-5`，并列出四项不支持能力。它不含独立逻辑，改规则只需改 `SKILL.md`。

## 5. 输入输出示例

### 示例 A：信息密集的技术文章

输入（`tests/sample-rice.md` 节选，实际输入为全文）：

```
在水稻中，单位面积穗数与每穗粒数之间存在明显的负相关：群体密度上升时，单株分蘖减少、
穗形变小，但总穗数增加，群体总粒数通常仍然上升，直到遮阴和养分竞争导致结实率大幅下降为止。

叶面积指数（LAI）是联系群体与个体的关键指标。LAI 低于 4 时光合截获不足；LAI 在 5 到 6
之间通常对应较高的群体光合速率；LAI 超过 7 后，下层叶片长期处于补偿点以下，成为消耗器官，
同时通风差、湿度高，稻瘟病与纹枯病风险上升。
```

输出（首行为 skill 要求的"来源 + 张数"；全文共 6 张，这里取前两张）：

```
源文件 tests/sample-rice.md — 共 6 张卡。

### Card 1 — 单位面积穗数与每穗粒数的负相关及其边界

**核心知识 / Core knowledge:** 水稻单位面积穗数与每穗粒数之间存在明显的负相关。

**解释 / Explanation:** 密度上升时单株分蘖减少、穗形变小，但总穗数增加，所以群体总粒数
通常仍然上升——个体变弱换来群体变大。这条上升有边界：直到遮阴和养分竞争使结实率大幅下降。

**例子或自测 / Example or self-test:** 问：密度升高后为什么群体总粒数仍能上升，又在哪里停住？
答：单株穗形变小被总穗数增加抵消；直到遮阴与养分竞争导致结实率大幅下降才停。

### Card 2 — LAI 三段阈值：4 以下不足、5–6 高效、7 以上转为消耗

**核心知识 / Core knowledge:** 叶面积指数（LAI）是联系群体与个体的关键指标：低于 4 光合
截获不足，5 到 6 通常对应较高的群体光合速率，超过 7 后下层叶片长期处于补偿点以下、成为消耗器官。

**解释 / Explanation:** 前两个区间讲截光够不够，7 以上讲叶片是净贡献还是净消耗；LAI 过高
还伴随通风差、湿度高，稻瘟病与纹枯病风险上升，这是病害代价而不是光合代价。

**例子或自测 / Example or self-test:** 问：LAI 从 6 升到 8，损失来自哪两方面？
答：下层叶低于补偿点成为消耗器官；湿度升高带来稻瘟病与纹枯病风险。
```

原文没有叙述性案例，因此每张卡都走自测问题分支——这是 skill 的规定，不是遗漏。

### 示例 B：低信息量输入

输入：`tests/sample-thin-notice.txt`（校园马拉松公告）。

输出：

```
源文本（校园马拉松公告）为一次性活动的会务安排，无知识点可提取，未凑数。
适合做知识卡的材料：教材章节、论文方法与结果、技术文档、记录了"为什么"的学习笔记。
```

### 示例 C：不支持的输入

输入：`把这篇 https://example.com/paper 做成知识卡`

输出（按用户提问语言拒绝，不代为抓取）：

```
不能从 URL 做知识卡：本 skill 只处理粘贴的纯文本或本地 .md/.txt 文件，不支持网页
（也不支持 PDF、图片、音视频、Anki 导出）。把正文粘给我，或给我一个本地文件路径。
```

## 6. 实测记录

四个 `tests/` 样例各针对一条规则，最后一列为本地实测结果：

| 样例 | 考察点 | 实测结果 |
| --- | --- | --- |
| `sample-rice.md`（中文，信息密集） | 去重、跨卡引用 | 6 张；解释改为引用 `与 Card 1 呼应`，不复述他卡数字 |
| `sample-caffeine.txt`（中文，同义反复） | 合并重复表述 | 6 张；"半衰期约 5 小时"原文出现 3 次只成一张卡 |
| `sample-sparse-en.txt`（英文，稀疏草稿） | 不编造、保留限定语 | 5 张；保留 "people say" / "I forget"，未补 0.5 丢弃率等常识 |
| `sample-thin-notice.txt`（中文，会务公告） | 不凑数 | 0 张并说明原因 |

另用一份约 3000 字的《2024 年水稻重大病虫害防控技术方案》实测，候选点约 15 个，输出 8 张卡，未卡片化的次要名录（如赤眼蜂参数、单项农艺措施）在结尾一行说明。

## 7. 仓库结构

```
skills/make-knowledge-cards/
├── SKILL.md              # skill 本体：工作流、卡片格式、硬性规则、输入处理
└── agents/openai.yaml    # 供非 Qoder agent 加载的清单，入口指向 SKILL.md
scripts/quick_validate.py # 结构与 frontmatter 校验
tests/                    # 4 类测试样例
LICENSE                   # MIT
README.md                 # 本文件
```

## 8. 校验

```bash
python scripts/quick_validate.py                    # 默认校验 skills/make-knowledge-cards
python scripts/quick_validate.py path/to/other-skill
```

检查项：`SKILL.md` 存在、frontmatter 由 `---` 包裹、`name` 为 hyphen-case 且与目录同名、`description` 单行且 ≤1024 字符、正文 <500 行、YAML 可解析（本机装有 PyYAML 时才做）、无 `TODO:`、skill 目录内无 `README.md` / `CHANGELOG.md` 等多余文档。当前结果：16/16 通过。
